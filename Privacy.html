KYRO — Details, Privacy & Authentication

KYRO — AI, Simplified.

Version 1.0.0 Build KYRO-2026.09.07 Established 2026

1. KYRO क्या है?

KYRO एक mobile-first AI assistant / AI chat application है। इसमें chat, conversation history, attachments, local Library, voice input, read-aloud, Voice Mode, Web Search/research workflows, profile, themes, Settings, API Manager, Model Manager, Backup/Restore और Security controls उपलब्ध हो सकते हैं।

Founder: MR. NITIN KUSHWAHA.

2. Google Login / Sign-In

✓ Google Sign-In मौजूद है। Current app में Google authentication Firebase Authentication के जरिए implement किया गया है। Google account की authentication Firebase संभालता है; KYRO को आपका Google password नहीं मिलता।

  • Google login के लिए Firebase का Google authentication provider इस्तेमाल होता है।
  • पहली बार account chooser खुल सकता है; पहले से session होने पर login तेज हो सकता है।
  • Firebase authentication session के कारण वापसी पर user को हर बार sign-in करना जरूरी नहीं हो सकता, जब तक logout/session clear न हो।
  • Google login के बाद app email, display name और profile photo जैसी उपलब्ध account जानकारी को KYRO user record से जोड़ सकता है।

3. Local Account Login

KYRO में local/demo account flow भी मौजूद है। Username और password browser/device के local storage में account record के रूप में रखे जा सकते हैं। Current described flow में password plain text में नहीं, SHA-256 hash के रूप में रखा जाता है।

Browser/site data हटाने पर local account data भी हट सकता है।

4. कौन-सा user data रखा जा सकता है?

  • Chat/conversation history
  • Projects
  • User name और profile information
  • Profile photo
  • Theme और app preferences
  • Library / attachment state
  • Authentication/session state
  • App settings और अन्य supported state

Current Firebase sync flow user state को Firebase Firestore के users/{uid} document से save/load कर सकता है। Google email, Google display name और Google photo भी user record के साथ save किए जा सकते हैं।

5. Chat और AI Processing

जब connected AI feature enabled होता है, user द्वारा भेजा गया text answer बनाने के लिए configured AI service को भेजा जा सकता है। Demo/offline mode में local या scripted responses हो सकते हैं। कौन-सा service इस्तेमाल होगा यह deployment/configuration पर निर्भर करता है।

Important: AI chat को पूरी तरह device-only/private मानकर confidential information भेजने से बचें, जब तक deployment की final privacy configuration इसकी पुष्टि न करे।

6. Voice, Microphone और Voice Mode

  • Microphone तभी इस्तेमाल होना चाहिए जब user voice feature शुरू करे।
  • Speech-to-text में audio transcription service को भेजा जा सकता है, configuration के अनुसार।
  • Real-time Voice Mode live microphone audio को connected real-time service तक stream कर सकता है।
  • KYRO को permanent microphone recording app के रूप में describe नहीं किया जाना चाहिए जब तक अलग recording feature enabled न हो।

7. Photos, Files और Documents

User द्वारा चुनी गई photos, camera captures, files और documents conversation में attach किए जा सकते हैं और local Library में दिखाई दे सकते हैं। AI analysis की जरूरत होने पर selected content/prompt configured AI service को भेजा जा सकता है।

8. Web Search / Research

Web Search या research workflow enabled होने पर search queries external web/search services तक जा सकती हैं। Returned information को AI answer तैयार करने के लिए process किया जा सकता है। Search results/citations third-party sources से आ सकते हैं।

9. API Keys और Security

  • User-configured API keys current web build में browser/device state में रखी जा सकती हैं।
  • Private API key को chat, GitHub या public post में कभी share न करें।
  • Current backup implementation में API keys शामिल हो सकती हैं; exported .kyro backup को sensitive file मानें।
  • App Lock/PIN device-local control है; इसे full encryption या unbreakable security न मानें।
  • KYRO absolute/100% uncrackable security का दावा नहीं करता।

10. Backup & Restore

KYRO का backup export chats, projects, profile/theme information और अन्य supported app data रख सकता है। Current implementation में configured API keys भी backup में आ सकती हैं। Backup file user के control में रहती है और export होने के बाद KYRO उसे अपने-आप protect या delete नहीं करता।

11. Logout और Data Deletion

Logout connected authentication session को समाप्त कर सकता है। लेकिन local chats, files, API keys और अन्य device data को अलग clear-data/delete action की जरूरत हो सकती है। Exported backups logout के साथ automatically delete नहीं होते। Production deployment में account/data deletion process स्पष्ट रूप से उपलब्ध होना चाहिए।

12. Third-Party Services

Deployment के अनुसार KYRO Google/Firebase authentication, connected AI services, search services और अन्य configured services के साथ interact कर सकता है। हर third-party service की अपनी privacy policy और terms होती हैं। Final production privacy policy में केवल वही providers सूचीबद्ध किए जाने चाहिए जो उस deployment में वास्तव में enabled हों।

13. Children & Sensitive Information

Passwords, financial credentials, private API keys, government IDs या अन्य highly sensitive information को AI prompts/uploads में न भेजें, जब तक selected service और deployment specifically उस information को handle करने के लिए designed न हों।

17. Production Security Checklist

  • Firebase Authentication में केवल required providers enable रखें।
  • Firestore Security Rules में हर user को केवल अपने users/{uid} data तक access दें।
  • Real API keys frontend/GitHub में न रखें; server-side environment variables में रखें।
  • GitHub Pages पर backend secrets upload न करें।
  • Privacy Policy में केवल वास्तव में enabled services/data flows लिखें।
  • Account deletion और user-data deletion का वास्तविक server-side process रखें।
